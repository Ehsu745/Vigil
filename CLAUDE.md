# CLAUDE.md

The data folder `~/.dodeca-core` and the `DODECA_*` environment variables keep the old name until the hooks are reinstalled; renaming them means running `install_hooks.py --apply`, which needs the user's OK.

The work log is the sibling vault `../vigil-folio` (private, `zelvet-velvet/vigil-folio`); the skills in `.claude/skills/` (`cmd-sync`, `test-queue`, `git-workflow`, …) are links into it. Record ideas and open tasks in its `LLM/DEV_STATUS.md` Ongoing, decisions and their reasons in `Notes/Vigil.md`, tests in `Quest/Test Queue.md`; not in Claude's own memory, which stays on one machine. When asked whether something is recorded, search the vault first.

Vigil (formerly dodeca-core) shows every running Claude Code session as a glowing polyhedron, either in the terminal or in a floating macOS panel. A Claude Code hook appends events to a JSONL file, and a C program reads that file, runs a state machine per session and draws the result with its own software renderer.

## Build and run

```sh
make                          # builds ./vigil (C11, links zlib and libm)
./vigil --demo                # fake sessions cycling through every state; q quits
sh mac/build.sh               # builds Vigil.app and its launcher script ./vigil-panel (macOS floating panel)
./vigil-panel --demo
```

`vigil`, `Vigil.app` and the `./vigil-panel` launcher are build output and are gitignored. Don't commit them. The launcher starts the app with `open -n -W` so macOS attributes microphone and speech permissions to the app (a binary started straight from the terminal would count as iTerm2); it passes `--tty` and `--launcher-pid`, and the app quits when the launcher ends.

## Checking a change

There is no test suite. To check a visual change without a terminal, render one demo frame to a file and look at it:

```sh
./vigil --snapshot /tmp/f.ppm --at 10 --size 720x400   # state of the 3-session demo 10 s in
python3 -c "from PIL import Image; Image.open('/tmp/f.ppm').save('/tmp/f.png')"
```

`--at` picks the moment in the demo script (`SCRIPT` in `src/session.c`): session N starts 3.7·N s in, and one cycle through all states takes about 27 s. Build with no new warnings (`-Wall -Wextra`).

## Layout

```
Claude Code ──hook.py──▶ ~/.dodeca-core/events.jsonl ──tail──▶ state machine ──▶ renderer ──▶ terminal / panel
```

- `src/vigil.h`: every shared type and function, grouped by the file that implements it. Start here.
- `src/events.c`: follows the JSONL file and parses lines into `Event`.
- `src/session.c`: event → state mapping, timings (`HOLD_WORK`, `CHEER_FOR`, `SLEEP_AFTER`, `DROP_AFTER`), the per-state appearance table `LOOKS`, how often a picture is redrawn (`session_rate` for the terminal, `panel_rate` and the Smoothness presets `SMOOTH` for both panels), and the built-in demo.
- `src/geom.c`: polyhedron shells (`dodeca`, `bucky`, `geo2`, `geo3`).
- `src/motion.c`: how the shell moves (the "Core Bestiary" design): snap turns (`Motion.q`), random patch cuts and their offsets, layer turns, spikes, scan plane, inner shell, and one routine per state (`think`, `work`, `swim`, `unlock`, the cases in `motion_tick`), plus the geometric whims. Nothing overshoots: fixed easing curves or critically damped following. Patches need the triangles of the geodesic shells.
- `src/render.c`: draws into a float RGB `Canvas`; draws the shell per triangle when patches have moved.
- `src/main.c`: terminal main loop, the output modes (kitty / iTerm2 inline PNG / half-block cells), options, `--snapshot`.
- `mac/panel.m`: the floating panel. It reuses `events.c`, `geom.c`, `session.c` and `render.c`, but not `main.c`.

A new routine is an `RT_*` name in `vigil.h`, a function `r_name(Ctx *c)` in `motion.c` and its row of `ROUTINES` there (name, the state it is for, run, optional enter, description); its working state is its own struct in the `RoutineState` union (`Motion.rs`, zeroed as it starts), never shared fields. A state picks one of its routines at random each time it starts, and the Windows Settings window's Motions page edits the map (kept in `panel-settings-win.json` as `mapRoutines` / `mapActions`; 32-bit masks, checked at compile time). ## Rules

- **After any change, restart the panel for the user.** Stop the running Vigil build (Windows: `taskkill.exe /IM vigil-panel.exe /F`; macOS: quit `Vigil.app`), rebuild it (`sh win/build.sh` or `sh mac/build.sh`), and start it again on the real sessions in the background (`./vigil-win`, or `./vigil-panel`), so the user can try the change at once. A running `vigil-panel.exe` locks the file, so the build fails until it is stopped.
- **The hook must never get in Claude Code's way.** `hook.py` always exits 0, prints nothing and finishes fast. It writes each event with a single `O_APPEND` write so concurrent sessions don't interleave lines.
- **Privacy:** the event file holds only time, session id, event name, folder name (not the full path), tool name and notification type, and on a subagent's events (`SubagentStart`, `SubagentStop`, and the tool events fired inside one) its agent id `aid` and type `at`. Never add prompts, tool input/output or paths. The file is mode 600 and its directory 700. The one exception is opt-in: with `DODECA_RICH=1` the hook keeps the last reply and notification text, the iTerm2 session id, the tmux pane id (`%N`, where a reply typed in the Windows panel goes), the Windows Terminal tab id it runs in (`wt`, `WT_SESSION`, the same), the pid of the `vigil-claude` launcher it runs under (`inbox`, the same) and the last 5 turns (`turns`: prompt `p` up to 2000 characters, reply `r`, the last 16 steps `s` as [tool, short detail], Claude's words between them as `["@say", text]` (`latest_said`: its newest text in the transcript's tail, up to 300 characters) and a task's notice as `["@notice", summary]`, their count `n` and tally `c`; `run` is the step running now) in `~/.dodeca-core/msg/<sid>.json` (600, written to a temp file and renamed under a lock, at most 4000 characters per text and about 24 KB of turns, deleted on `SessionEnd`); the event line only gets `"m": 1`. A session whose turns began before the hook kept them gets them once from its transcript (`backfill`, at most the last 4 MB, on its next prompt or Stop, or at once on `SessionStart` with `source` `resume`, the reply too; `filled` marks it done). A subagent's final reply (`last_assistant_message` of `SubagentStop`, or the report it handed back with `SubagentHandback`, `hb`) goes into `msg/<sid>-<aid>.json`, deleted with the session's; its steps stay out of the session's turns. A step's detail is `step_detail` in `hook.py`: a command's own `description`, else its first line, a file's base name (never its folder), a pattern, a domain. A prompt that is the harness's own line (`HARNESS`: a background task's `<task-notification>`, `<system-reminder>`, …) starts no turn: a task's notice is an `@notice` step of the turn going on (its `<summary>`, cut at 80), so the turn keeps your prompt; the Windows panel shows such a turn kept by an older hook the same way (`harness_p`). Never put that text in `events.jsonl`.
- **No dependencies:** the Python scripts use only the standard library. The C code uses only libc, libm and zlib (plus Cocoa for the macOS panel, and libraries that are part of Windows for the Windows panel: gdi32, dwmapi, opengl32 and the like).
- **Don't run `python3 install_hooks.py --apply` or `--remove` without asking.** They edit the user's `~/.claude/settings.json`. Running it without flags is a dry run and is safe.
- **Blades is Zaviel's; Skein is Ehsu745's.** Blades (`r_blades` in `src/motion.c`) was designed by Zaviel ([zelvet-velvet](https://github.com/zelvet-velvet)), who wrote the Windows panel and also works on this code with Claude. PRs #10 and #11 rewrote it for every platform (`src/` is shared); Zaviel preferred the original, so it is back exactly as it was in `f9d16a1`, and the rewrite lives on as its own routine, **Skein** (`r_skein`, `RT_SKEIN`): home -1, so it is off by default everywhere and runs only where someone turns it on in Settings > Motions; it is last in the enum so saved Motions choices keep their bits. Don't change Blades without the user's OK, and tell Zaviel when a change to the shared motions changes how the Windows panel behaves.
- The labels use a built-in 3×5 bitmap font (ASCII letters, digits, a few symbols). Anything else renders as `?`.
